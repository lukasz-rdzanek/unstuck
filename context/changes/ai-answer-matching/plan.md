# AI Answer-Matching Implementation Plan

## Overview

When a learner posts a question in a lesson's chat, automatically surface the single most relevant prior answer from the whole course's past discussions — as a subtle, dismissible suggestion card below their message. Relevance is semantic (pgvector cosine similarity over message embeddings), with operator-seeded (`is_seeded=true`) answers boosted so curated content wins ties. Embeddings are generated by Cloudflare Workers AI (`@cf/baai/bge-base-en-v1.5`, 768-dim) from the existing Worker. This is the v2 evolution of the v1 curated-seeding rule: the curated seeds remain the quality anchor, but the growing peer-knowledge base becomes searchable too.

Build order is backend → embedding pipeline → match endpoint + UI → prod, mirroring how `learning-loop` shipped (local-first, prod as the final phase).

## Current State Analysis

**Message model** ([supabase/migrations/20260528122957_lesson_chat_schema.sql:91-106](supabase/migrations/20260528122957_lesson_chat_schema.sql#L91)):
- `messages(id, lesson_id, author_id nullable, body text 1..4000, is_seeded bool default false, created_at)`.
- Append-only and **immutable**: RLS has SELECT (gated by `has_course_access`) and INSERT (own, non-seed) policies, but **no UPDATE/DELETE policy** for `authenticated` ([20260528140054_lesson_chat_rls.sql:104-127](supabase/migrations/20260528140054_lesson_chat_rls.sql#L104)).
- **No rating / upvote / helpfulness data exists anywhere** in the schema. "Best" must be defined without crowd signal → we use semantic relevance + seed-boost.

**Access control** ([20260528122957_lesson_chat_schema.sql:116-130](supabase/migrations/20260528122957_lesson_chat_schema.sql#L116)): `has_course_access(p_course_id)` is a `STABLE SECURITY DEFINER` SQL fn (free course OR enrolled). It is the sole gating fn and is reused by both `lessons` and `messages` SELECT policies — our match RPC reuses it too, so course-scoped access control comes for free.

**Chat UI / data flow**:
- React island `ChatPanel` ([src/components/chat/ChatPanel.tsx:42](src/components/chat/ChatPanel.tsx#L42)) composed inside `LessonAside` ([src/components/lesson/LessonAside.tsx:348](src/components/lesson/LessonAside.tsx#L348)), hydrated `client:load` from the lesson page ([src/pages/courses/[slug]/lessons/[lessonSlug].astro:209](src/pages/courses/%5Bslug%5D/lessons/%5BlessonSlug%5D.astro#L209)).
- State + Realtime live in the `useChatMessages` hook ([src/components/chat/useChatMessages.ts:60](src/components/chat/useChatMessages.ts#L60)); `postMessage` ([useChatMessages.ts:286](src/components/chat/useChatMessages.ts#L286)) does the optimistic insert.
- **Chat has no API routes** — it talks directly to the Supabase browser client ([src/lib/supabase-browser.ts](src/lib/supabase-browser.ts)) for reads, inserts ([src/lib/services/messages.ts](src/lib/services/messages.ts)), and Realtime `postgres_changes`. This working flow must NOT be disturbed (see [[feedback-no-db-reset]]: big changes must not break working features).

**Cloudflare runtime** ([astro.config.mjs](astro.config.mjs), [wrangler.jsonc](wrangler.jsonc)):
- Astro 6, `output: "server"`, `@astrojs/cloudflare` adapter. In v6, bindings are accessed via `import { env } from "cloudflare:workers"` — `Astro.locals.runtime.env` is REMOVED.
- `wrangler.jsonc` has only an `ASSETS` binding today; `compatibility_flags: ["nodejs_compat"]`.
- `npm run dev` runs in **workerd** via the Cloudflare vite plugin, so bindings are available locally — but Workers AI is not emulated (calls proxy to the real Cloudflare API; needs account credentials).

**Answer-key lesson** ([context/foundation/lessons.md](context/foundation/lessons.md)): the `enable-not-force RLS + definer-owned function` pattern is the project's established way to expose derived/gated data without leaking the source. We follow the same owner-owned `SECURITY DEFINER` discipline for both the match RPC and the embedding-write fn.

## Desired End State

A signed-in learner with course access types a question into a lesson's chat and posts it. Within ~1–2s a subtle "You might find this helpful" card appears directly beneath their message, showing the single best matching prior answer, a "from <lesson title>" label when it came from another lesson, and a dismiss (×). If nothing clears the relevance threshold, no card appears (silent). The matched answer respects course access (a learner never sees content from a course they can't access). Operators seed curated answers as before; those rank first on ties. Verified locally, then deployed to prod with a one-shot embedding backfill.

### Key Discoveries:

- No rating data exists → "best" = cosine relevance + seed-boost ([20260528122957_lesson_chat_schema.sql:91](supabase/migrations/20260528122957_lesson_chat_schema.sql#L91)).
- `has_course_access` is reusable for the match RPC's gating ([20260528122957_lesson_chat_schema.sql:116](supabase/migrations/20260528122957_lesson_chat_schema.sql#L116)).
- `messages` is immutable (no UPDATE policy) → embedding writes need a narrow owner-owned `SECURITY DEFINER` fn; `service_role` is intentionally absent from the app env (per AGENTS.md), so we cannot bypass RLS from the Worker any other way.
- Astro v6 binding access is `import { env } from "cloudflare:workers"` ([astro.config.mjs](astro.config.mjs)); PostgREST can't run pgvector operators, so the similarity query must be wrapped in an RPC.
- Chat inserts stay on the browser path; embeddings are produced asynchronously ("lazy embed") so the working insert/Realtime/optimistic flow is untouched.

## What We're NOT Doing

- **No rating/upvote/helpfulness system** — explicitly deferred; "best" is relevance + seed-boost only.
- **No change to the message insert/Realtime/optimistic path** — inserts remain browser-direct; we do not route them through a server endpoint.
- **No as-you-type / pre-send matching** — matching fires only after a successful post.
- **No cross-course or global matching** — corpus is the current course only.
- **No multiple suggestions** — exactly top-1 above threshold.
- **No queue/cron infra (pgmq/pg_net/pg_cron)** — backfill is an idempotent operator-triggered endpoint, not an autonomous pipeline.
- **No re-embedding on edit** — messages are immutable, so embeddings never go stale.
- **No answer-quality moderation / LLM rerank** — pure vector similarity + seed-boost.

## Implementation Approach

pgvector stores a 768-dim embedding per message. A learner's posted question is embedded on the fly (Workers AI), then a `SECURITY DEFINER` RPC (`match_lesson_answers`) ranks the course's embedded messages by cosine distance — excluding the asker's own messages, the just-posted message, and trivially short messages — boosting seeded rows, and returns the single best row above a threshold (or nothing). Stored-message embeddings are produced by an operator-triggered backfill endpoint that calls Workers AI and writes via a narrow definer fn (because the table is immutable to `authenticated` and `service_role` is unavailable). The UI adds a dismissible suggestion card rendered after a post inside the existing chat island, leaving the proven insert/Realtime flow intact.

## Critical Implementation Details

- **Workers AI in local dev needs Cloudflare credentials.** `npm run dev` runs in workerd, but `@cf/baai/bge-base-en-v1.5` calls proxy to the real Cloudflare API. Local verification of Phases 2–3 requires `wrangler login` (or `CLOUDFLARE_ACCOUNT_ID` + a `CLOUDFLARE_API_TOKEN` with Workers AI access available to the dev runtime). Without this, embedding calls fail locally — this is a prerequisite, not a code bug.
- **Embedding model dimensionality is load-bearing.** `bge-base-en-v1.5` returns 768 dims; the `vector(768)` column, the HNSW index, and both embed call sites (backfill + query) must use the *same* model. Changing the model later requires a re-embed + column change. Normalize/compare with cosine (`<=>`), or use inner product (`<#>`) only if vectors are confirmed normalized.
- **The immutable-table write must be column-scoped.** `set_message_embedding` updates ONLY the `embedding` column, ONLY where it is currently `NULL`, and never touches `body`/`author_id`/`is_seeded`. This keeps message immutability intact for everything except derived embeddings.
- **Vector index ordering.** Order the RPC by the raw distance operator (`embedding <=> query`) so the HNSW index is used; do not order by a computed `similarity` alias. Apply the threshold and seed-boost without defeating the index (filter on distance; boost via a final ordering tier).
- **Match RPC must omit nothing sensitive but leak nothing cross-course.** It returns only `body`, `lesson_id`, lesson `slug`+`title`, `is_seeded`, and `similarity`; the `has_course_access` gate is applied to the *target* course inside the definer fn so a caller can only ever match within a course they can access.

## Phase 1: Vector schema + match RPC (backend/DB)

### Overview

Enable pgvector, add an embedding column + index to `messages`, and create the two owner-owned `SECURITY DEFINER` functions: the read-side matcher and the narrow embedding writer. No app code yet.

### Changes Required:

#### 1. Migration — pgvector + embedding column + index

**File**: `supabase/migrations/<timestamp>_message_embeddings.sql`

**Intent**: Add semantic-search storage to the existing `messages` table without altering its immutability contract.

**Contract**:
- `create extension if not exists vector with schema extensions;`
- `alter table public.messages add column embedding extensions.vector(768);` (nullable — backfilled later).
- HNSW index for cosine: `create index messages_embedding_hnsw on public.messages using hnsw (embedding extensions.vector_cosine_ops);`
- Keep the existing `messages_lesson_seed_created_idx` untouched.

#### 2. Migration — match RPC

**File**: same migration file

**Intent**: Rank a course's embedded messages against a query embedding, gated by course access, with candidate filtering and seed-boost, returning the single best match (or no row).

**Contract**: `create function public.match_lesson_answers(p_course_id uuid, p_query_embedding extensions.vector(768), p_exclude_author uuid, p_exclude_message_id uuid, p_match_threshold float, p_match_count int) returns table(message_id uuid, lesson_id uuid, lesson_slug text, lesson_title text, body text, is_seeded boolean, similarity float)` — `language sql STABLE SECURITY DEFINER set search_path = public, extensions`. Logic:
- Guard: `where public.has_course_access(p_course_id)` (whole predicate yields zero rows if no access).
- Join `messages m` → `lessons l` on `m.lesson_id = l.id and l.course_id = p_course_id`.
- Candidate filter: `m.embedding is not null and m.id <> p_exclude_message_id and (m.author_id is distinct from p_exclude_author) and char_length(m.body) >= 40`.
- Threshold: `1 - (m.embedding <=> p_query_embedding) >= p_match_threshold`.
- Order: seed-boost first, then distance — `order by m.is_seeded desc, m.embedding <=> p_query_embedding asc` (raw operator preserves index use); `limit least(p_match_count, 5)`.
- `similarity` computed as `1 - (m.embedding <=> p_query_embedding)`.
- `revoke all on function ... from public; grant execute ... to authenticated;`

#### 3. Migration — narrow embedding writer

**File**: same migration file

**Intent**: Allow embeddings to be written to the otherwise-immutable `messages` table, column-scoped and null-only, from the Worker (no `service_role` available).

**Contract**: `create function public.set_message_embedding(p_message_id uuid, p_embedding extensions.vector(768)) returns void` — `language sql SECURITY DEFINER set search_path = public, extensions` doing `update public.messages set embedding = p_embedding where id = p_message_id and embedding is null;`. Plus a batch reader for the backfill: `create function public.list_unembedded_messages(p_limit int) returns table(id uuid, body text) ... security definer` returning `id, body where embedding is null order by created_at limit least(p_limit, 200)`. `revoke from public; grant execute to authenticated;` (acceptable: both only touch derived embeddings / read body the caller could already read via RLS within accessible courses — but since backfill is operator-gated at the API layer, exposure is minimal).

#### 4. Regenerate DB types

**File**: `src/lib/db/database.types.ts`

**Intent**: Pick up the new column + functions for type-safe `rpc()` calls.

**Contract**: `npx supabase gen types typescript --local | grep -v "^Connecting"` → overwrite file. `messages.Row` gains `embedding: string | null` (pgvector serializes as string over PostgREST).

### Success Criteria:

#### Automated Verification:

- Migration applies: `supabase migration up`
- Types regenerated with no further diff
- Type check passes: `npx astro check`
- Lint passes: `npm run lint`
- Build succeeds: `npm run build`

#### Manual Verification:

- `vector` extension present; `messages.embedding` column + HNSW index exist (psql `\d public.messages`).
- `match_lesson_answers` returns `[]` for a course the caller can't access (gating works) — verified via psql as a non-enrolled role / SQL probe.
- `set_message_embedding` updates a NULL embedding and is a no-op on an already-embedded row; cannot alter `body`.

## Phase 2: Embedding pipeline (Workers AI + backfill)

### Overview

Add the Workers AI binding and an embedding helper, then an operator-gated backfill endpoint that embeds all NULL-embedding messages in batches. Insert path stays untouched ("lazy embed").

### Changes Required:

#### 1. Workers AI binding

**File**: `wrangler.jsonc`

**Intent**: Make the `AI` binding available to the Worker in local dev and prod.

**Contract**: add top-level `"ai": { "binding": "AI" }`. No `astro.config.mjs` change needed.

#### 2. Embedding helper

**File**: `src/lib/embeddings.ts`

**Intent**: One place that turns text into a 768-dim vector via Workers AI, used by both the backfill and the live query.

**Contract**: `export async function embedText(text: string): Promise<number[]>` — `import { env } from "cloudflare:workers"`; call `env.AI.run("@cf/baai/bge-base-en-v1.5", { text: [text] })`; return the first embedding array. Lowercase + trim + clamp length before embedding. Export the model id + dim (`768`) as constants so the column and helper can't drift. Throw a typed error on binding/response failure (callers treat embedding as best-effort).

#### 3. Backfill API route

**File**: `src/pages/api/embeddings/backfill.ts`

**Intent**: Operator-triggered, idempotent batch embedding of messages lacking an embedding.

**Contract**: `export const prerender = false;` + `POST`. Gate: `context.locals.user?.id` must equal the operator UUID (read from an `astro:env/server` var, e.g. `OPERATOR_USER_ID`); else 403 `{error}`. zod body `{ batchSize?: number }` (default 50, max 200). Flow: `supabase.rpc("list_unembedded_messages", {p_limit})` → for each, `embedText(body)` → `supabase.rpc("set_message_embedding", {p_message_id, p_embedding})`. Return `{ok, embedded: <count>, remaining: <count> }`. No throws across the boundary; partial failures are counted and reported, not fatal (best-effort, matches `learning-loop`'s auto-schedule posture). Caller re-invokes until `remaining = 0`.

#### 4. Operator UUID env var

**File**: `astro.config.mjs` (env.schema) + `.dev.vars`

**Intent**: Make the operator gate configurable, not hardcoded.

**Contract**: declare `OPERATOR_USER_ID` as `envField.string({ context: "server", access: "secret", optional: true })`; set it in `.dev.vars` to the local operator id and (later) as a prod secret. If unset, the backfill route returns 503 `{error: "backfill disabled"}` (fail-closed).

### Success Criteria:

#### Automated Verification:

- Type check passes: `npx astro check`
- Lint passes: `npm run lint`
- Build succeeds: `npm run build`
- Build leak-check: `embeddings.ts` / binding code not inlined into the client bundle (`grep -r "cloudflare:workers" dist/client/` → empty).

#### Manual Verification:

- With Cloudflare creds available locally, POST `/api/embeddings/backfill` embeds existing seeded + peer messages; re-running drains `remaining` to 0 and is a no-op thereafter (idempotent).
- Non-operator user → 403; operator → 200 with counts.
- `messages.embedding` populated for previously-NULL rows (psql count of NULL embeddings drops to 0).

## Phase 3: Match endpoint + chat suggestion card (API + UI)

### Overview

Add the live match endpoint and wire a dismissible suggestion card into the chat island, fired after a successful post. No disruption to the existing insert/Realtime flow.

### Changes Required:

#### 1. Match API route

**File**: `src/pages/api/lessons/[lessonId]/match-answer.ts`

**Intent**: Embed a learner's question and return the single best prior answer in the same course, or nothing.

**Contract**: `export const prerender = false;` + `POST`. Auth required (`context.locals.user`, else 401). zod body `{ question: string (1..4000), excludeMessageId?: string(uuid) }`. Flow: resolve `course_id` from `lessonId` (read service, RLS-gated); `embedText(question)`; `supabase.rpc("match_lesson_answers", { p_course_id, p_query_embedding, p_exclude_author: user.id, p_exclude_message_id, p_match_threshold: ~0.72, p_match_count: 1 })`. Return `{ ok, match: null | { messageId, lessonSlug, lessonTitle, body, isSeeded, similarity } }`. Embedding failure → `{ok, match: null}` (degrade silently, never 500 the chat).

#### 2. Match service helper

**File**: `src/lib/services/answer-match.ts`

**Intent**: Read-only helper resolving the lesson→course and shaping the RPC call/result.

**Contract**: `getCourseIdForLesson(supabase, lessonId): Promise<string | null>` and `matchAnswer(supabase, {courseId, embedding, excludeAuthor, excludeMessageId}): Promise<AnswerMatch | null>`. Types `AnswerMatch` in `src/types.ts`.

#### 3. Suggestion card component

**File**: `src/components/chat/AnswerSuggestionCard.tsx`

**Intent**: Subtle, dismissible "You might find this helpful" card showing the matched answer.

**Contract**: props `{ match: AnswerMatch, currentLessonId: string, onDismiss: () => void }`. Renders body (clamped, markdown-safe plain text — no `dangerouslySetInnerHTML`), a "from <lessonTitle>" link when `match.lessonId !== currentLessonId`, a seeded badge when `isSeeded`, and a × dismiss. Styled with `cn()` + existing glass/semantic tokens; light/dark + responsive. Use a React component (it holds dismiss state / event handler) per AGENTS.md.

#### 4. Wire into the chat island

**File**: `src/components/chat/useChatMessages.ts` + `src/components/chat/ChatPanel.tsx`

**Intent**: After a learner's post lands, fetch a match and render the card beneath that message; dismiss removes it; only one active suggestion at a time.

**Contract**: in `useChatMessages`, after `postMessage`'s insert resolves successfully, fire-and-forget `fetch("/api/lessons/<lessonId>/match-answer", {question: body, excludeMessageId})`; store `suggestion: AnswerMatch | null` + `dismissSuggestion()` in hook state. `ChatPanel` renders `<AnswerSuggestionCard>` after the relevant message when `suggestion` is set. Must not block or alter the optimistic-post / Realtime echo path; a failed/empty match is a silent no-op.

## Performance Considerations

- HNSW index keeps similarity queries fast well past MVP scale; order by the raw distance operator to preserve index use.
- One Workers AI embed call per posted question (after-post, fire-and-forget) — negligible and off the critical render path.
- Backfill batches (≤200) bounded by `list_unembedded_messages`'s `limit least(p_limit, 200)`.

## Migration Notes

- Embedding column is nullable + backfilled; no data migration of existing rows beyond the backfill endpoint. Messages stay immutable except for the derived embedding.
